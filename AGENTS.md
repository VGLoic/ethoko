# Agent Guidelines for Ethoko Monorepo

Guidelines for AI coding agents working in the Ethoko monorepo.

## Project Overview

Ethoko is a warehouse for smart-contract compilation artifacts. It enables teams to version, store, and share smart-contract compilation artifacts, decoupling compilation from operation.

Ethoko supports different storage backends:
- **Filesystem**: Local directory storage - ideal for development and testing
- **AWS S3**: Cloud storage for production use,
- **Ethoko Central**: Hosted backend service for artifact storage and management (in development)

Ethoko supports the compilation artifacts generated by both Hardhat (v2 and v3) and Forge.

**Monorepo Structure:**

- `packages/cli-beacon`: Standalone CLI for Ethoko artifact management (main package)
- `apps/central`: Ethoko Central backend service (in development)
- `apps/*`: Integration examples with different frameworks (e.g., Foundry and Hardhat)

## Build System

**Package Manager:** pnpm (use the version declared in root `package.json`)
**Build Tool:** Turborepo
**Node Version:** `nvm use`

Use package scripts as the canonical interface for routine development workflows.

## Test
**

### E2E Test Pattern for integration apps in `apps/`

**Test Framework:** Vitest with global setup, 60s timeout, located in `e2e-test/*.e2e.test.ts`.

**Key Points:**

- All tests run with the filesystem provider.
- All tests use the same `setup.ts`, `compilation-targets.ts` and `helpers/` for utilites.

## Validation Workflow

After each logical unit of work (feature, bug fix, todo item, or review-plan item), run the applicable root package command. Fix issues before proceeding:

- Central API or UI only: `pnpm validate:central`.
- CLI or framework integration apps only: `pnpm validate:cli`.
- Both areas, shared build/lint/type configuration, or workspace-wide dependencies: run both.

Validation checks formatting without rewriting files; use the separate formatting scripts for fixes.

Before Central integration tests or validation, start the shared database explicitly with `pnpm test:integration:db:start`. Tests leave it running. For prerequisites, focused tests, shared stop/clean coordination, or migration compatibility, see `docs/validation.md`.
